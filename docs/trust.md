# Compiler Trust Policy

## Gates enforced now

The current release gate establishes these facts:

- Lean-to-TypeScript elaborates the selected Lean declarations and rejects unsupported reachable IR before publication.
- Lean-to-TypeScript type-checks the complete generated tree and publishes it with a content-bound manifest through one transaction.
- TypeScript-to-Lean `--strict` rejects every degradation that the current compiler records before it writes source or build files.
- The CLI exposes no generated proof-placeholder path. Proofs use hand-authored Lean and the normal Lean gate.
- The JavaScript and refinement audits check their registered theorem sets against the closed axiom allowlist.
- Differential tests are reported as counterexample searches, not refinement proofs.
- Evidence freshness depends on content and toolchain identity, not a Git branch name.

These gates do not establish a whole-compiler refinement theorem. Non-strict
TypeScript-to-Lean output can contain reported degradation. Raw Lean syntax nodes and
source scanners still exist in the TypeScript-to-Lean compiler. The present audits cover their
registered sets, not every future program or analysis.

## Required before a proof-carrying claim

The following requirements are under construction. No artifact may claim the
proof-carrying guarantee until every applicable requirement is enforced.

1. Compilation is total over its declared input. Failure returns typed diagnostics and never becomes a placeholder or guessed implementation.
2. Printed code comes from typed syntax nodes. No raw-source node bypasses the semantic IR and printer.
3. Placeholder and trusted-base audits operate on parsed semantic structure, not source-text patterns.
4. Comment content cannot introduce declarations or change generated semantics.
5. The compiler fabricates no language instances or laws.
6. Platform behavior enters through an explicit capability, formal model, or named conditional runtime assumption.
7. Every exported theorem passes its transitive axiom gate.
8. Every analysis has a proved or checked complexity bound and an adversarial scaling oracle.
9. Every admitted Lean-to-TypeScript operation names its source semantics, target semantics, lowering theorem, emitted runtime body, and exact assumptions.
10. Generation fails when any reachable operation lacks its proof or certificate record.
11. The manifest binds semantic IR, proofs, certificates, compiler, runtime, generated bytes, source maps, and exact toolchains.
12. External assumptions are obligations to discharge through a certified adapter, runtime proof, or exact conformance evidence.
13. Publication requires every applicable proof, certificate, assumption record, and freshness check.
14. Synthesis accepts a candidate only when every proof and model obligation is closed.
15. Rejected candidates retain machine-readable diagnostics and no deployment authority.
