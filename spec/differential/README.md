# Model differential data

`primitive.json` and `abstract-operations.json` are the suite sources. They declare operation registries, fixed vectors, deterministic generators, and fixture graphs without storing expected results. `manifest.json` is generated by `bun run differential:generate`; `bun run differential:check` regenerates both the combined manifest and Lean operation registry in memory and rejects stale checked files.

The primitive slice preserves all 7,127 migrated executions without resampling. The combined manifest adds 97 abstract-operation vectors corresponding one-to-one with the legacy inventory plus canonical graph probes. `legacy-abstract-inventory.json` anchors the deleted files' `be709a4` hashes and represented ID/order/count; it does not claim per-observation output parity. Generators must not silently resample or deduplicate parity-preserving primitive vectors.

Canonical Number observations use exact binary64 bits. Every observed NaN is normalized to the quiet NaN bit pattern `9221120237041090560`; non-NaN payloads, including signed zero, retain their exact bits.

Graph fixtures cap each array index at `65535` and the aggregate dense model allocation at `65536` cells, computed as the sum of `maxIndex + 1` for every nonempty array node. Both validators reject over-budget graphs before materialization.

Every graph has `@object`, `@function`, and `@array` identities with the same kind and topology on both runtimes: object is the null-root, while callable function and array each inherit from object. Node uses the fresh VM's intrinsic objects so operators and iteration execute normally; Lean allocates the corresponding model identities. Their fixture-selected property sets are empty. `realm: true` additionally installs primitive-wrapper prototypes and does not change those three names. Registered symbol keys are namespaced as `tslean-differential:<key>` and use `Symbol.for` semantics, while local symbols remain allocation identities.

Canonical references are assigned once in encounter order across completion, trace, selected roots, prototypes, and descriptors. Standard runtime errors carry an identity plus normalized name and empty message; fixture-authored errors retain their UTF-16 message. Error classification reads only intrinsic prototype identity and own data descriptors.
